- (decision) The chosen project is a Basys3 drawing-and-physics puzzle inspired by Q REMASTERED; players use drawn objects to guide a ball to a level target.
- (decision) VGA is the gameplay display; the Pmod OLED presents level selection, objectives, drawing budget, and status; mouse, board controls, and LEDs support play.
- (decision) The first version is bounded to one ball and a few drawn objects, signed fixed-point physics, gravity and collisions, translation and bouncing; rotation is deferred.
- (decision) The full game must run in one bitstream within Basys3 resource limits and meet the course criteria for functionality, reliability, interface, and user experience.
- (event) Team responsibilities are divided among game control and drawing input, physics and world state, and graphics and displays; exact module contracts remain open.
- (assumption) The live-demo player is the primary user and EE2026 assessors are a secondary audience; validate this framing with the team.
- (assumption) Future expansion should deepen the same puzzle loop with more levels only after the bounded core is reliable.
- (event) The first integration milestone is to draw and release one object, let it fall and collide with the ball, then detect whether the ball reaches the target.
- (event) Resolve renderer-output inconsistency: the original project proposal assigns gameplay to VGA and OLED information screens, but one module table says the renderer draws into the OLED image.
- (decision by user) The final product uses mouse-only play, including stage selection and menus; course staff approved the exception to the manual switch requirement.
- (decision by user) Released strokes are bounded sampled polylines treated as rigid bodies with visible rotation.
- (decision by user) VGA carries the full lobby/gameplay view and overlays; the OLED carries stage, objective, allowance, and status.
