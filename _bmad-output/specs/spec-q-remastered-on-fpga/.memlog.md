- (decision) Split controller-to-physics into independent create and control request/response channels. One create and one control can be outstanding at the same time; control readiness cannot depend on the create/admission arithmetic being idle. A pause click after release can be captured while create validation is busy. Result receipt, operation commit and completion acknowledgement are distinct; no automatic resubmission after receipt. Once valid is raised, hold payload until ready transfer.
- (decision) Within the100MHz core, use same-clock ready/valid: sample transfer on rising edge only when !rst && valid && ready; source must assert valid independently of ready and hold data while stalled. Reset suppresses valid and makes in-flight operations uncommitted/cancelled per generation recovery. No combinational valid-from-ready dependency; no bare ready/valid crossing clock domains. This borrows handshake convention, not an AXI bus implementation. Primary reference https://docs.amd.com/r/en-US/pg101-axi-protocol-checker/AXI-Protocol-Checks-and-Descriptions .
- (decision) Control opcodes select load/reset/pause/resume/discard. A new-attempt load/reset/discard cancels stale uncommitted work; otherwise latched current goal has priority over pause and uncommitted creation. A valid pause during an already-running admission completes that atomic operation then freezes before more integration. For same-cycle pause and an unreceived create, pause is captured and create is cancelled; define every received request one terminal response. Response slots cannot be overwritten; no next same-channel request until prior response is consumed.
- (decision) Use shared enum encodings for modes/actions/control/result/reason/feedback/focus and faults, zero reserved where applicable. Create terminal statuses OK/REJECTED/CANCELLED/STALE are separate from reason NONE/OVERLAP/DEGENERATE/FULL/BAD_PAYLOAD/WRONG_STATE/COUNTER_EXHAUSTED. Only OK create returns a valid body ID and decrements allowance once. Invalid/stale completions are drained without effects.
- (decision) Identity policy: compare revisions unsigned only within the same attempt and prohibit arithmetic wrap or live ID reuse. Increment world revision on committed load/admission/pause/resume/outer update and retain the goal's exact winning revision. Local UI/view/frame/feedback counters have distinct ownership/meaning. Counter exhaustion quiesces with diagnostic instead of wrapping; rebasing requires all reliable transactions, mailboxes, snapshots and displayed identities drained/invalidated under coordinated protocol startup reset. A stage reset alone cannot silently recycle a still-live pair.
- (decision) Renderer join and ownership records include exact world revision plus full UIState (attempt/UI/view/feedback IDs and required-world barrier). FramePacket carries frame ID, bank, actual world revision and UIState. FrameAcknowledgement echoes identities and disposition PRESENTED/DROPPED_STALE/DROPPED_CANCELLED/FAULT plus released_bank_valid/released_bank. A dropped pending frame does not release the displayed front bank; the source reclaims its submitted back bank only after the handshake is fully idle.
- (decision) Frame transfer across100MHz/25.2MHz is an explicit four-phase held-data mailbox: request high with stable complete packet, destination commits/drop-ack at safe point, source lowers request after synchronized ack, destination lowers ack after synchronized request low, source waits for ack low before another send/reuse. Only req/ack are individually synchronized; payload and ack metadata are captured under the held-data protocol with explicit constraints. Frame ack for presentation waits for safe frame-boundary swap and old-bank read-pipeline drain; it is not receipt-only.
- (decision) Add a separate epoch mailbox carrying the controller's active attempt to pixel scanout. Apply epoch changes at a safe frame boundary with priority over frame swap, suppress stale pending frames and blank the old attempt until a matching new frame arrives. Drain any stale frame transfer with a dropped acknowledgement, not by deasserting an in-flight request early. Core waits for the desired epoch acknowledgement before publishing that attempt's frame. Physical startup states front bank0 invalid/back bank1 owned by renderer/requests and acks low.
